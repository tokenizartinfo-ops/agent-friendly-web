## Problem and design
The actual preparation consent GET requires one exact project query parameter in addition to normal OAuth parameters. The manually prepared client form currently has bare /authorize, so a later client could fail before consent. The token path is /oauth/token. Build a pure, frozen MCP server stanza from EXACT trusted internal issuer/projectId/clientId, using existing syntax parsers. Issuer is fixed to https://preparation-canary.agentfriendlyweb.dev; do not generalize to public AFW, another project product, caller URL or dynamic registration.
Export buildPreparationClientDraft(input) from lib/preparation-client-draft.mjs. Source-only, no runtime importer, UI action, network, storage, clocks, plugin installation or creator. Valid input returns draft_only/mcpServer, with authorizationUrl=/authorize?project=URL-encoded exact project, tokenUrl=/oauth/token, same issuer/resource, provided public client/none, baseScopes[afw:project:read], defaultScopes[afw:capsule:prepare], oidcEnabledfalse; top pkceMethodS256 and callbackValidationRequiredtrue. Freeze every nested layer. Invalid/extra/accessor configuration gives blocked/mcpServernull without echo.
createAllowed/registrationVerified/sourceVerified/consentGranted/authorizationGranted/operationalReadiness/executionAllowed/chargeAllowed/publicationAllowed alwaysfalse. Syntax is not proof of SDK registration or owner/domain facts. No guessed callback, secret, OAuthstate/challenge/refresh or DCR endpoint. Copy only after current profile/callback/registered metadata are independently verified, and obtain final concrete permission before creation/consent. Does not reopen the spent bootstrap journal.
