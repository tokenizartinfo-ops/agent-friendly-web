El siguiente paso de avisos no se completó antes de vencer; no hay consentimiento de avisos, admisiones, eventos ni procesos. Se cerró el Worker conservando historia y custodia. No pedir al usuario repetir códigos ni presentar el fallo como suyo.

La UI humana diferencia una prueba pausada, una ventana terminada y una prueba aún no iniciada cuando esos estados están determinados por configuración. No consulta identidad o SQL para mostrar ese estado administrativo, no revela owner/grants, no reabre ni renueva permisos. Conserva404 y no-store. ## Preparación repetible

scripts/prepare-own-monitor-original.mjs recibe JSON crudo de UNA lectura primaria acotada y la configuración de bootstrap propio, desde stdin. Conserva fechas UTC y milisegundos: no convertir datos con PowerShellConvertFromJson antes de parsear timestamps. Un borrador local anterior interpretó12/10 como10/12 y desplazó zona; se detectó antes de publicar. La preparación nueva rechaza fechas culturales, futuras, expiradas, permiso revocado, scopes extra, más de un original y recursos ajenos; puede acortar el límite al servicio, nunca ampliarlo.

Ejemplo operacional desde el repositorio AFW: capturar salida --json de la consulta exacta de la nueva ocurrencia y pasarla directamente al script con rutas de template y salida dentro de output. El script escribe conflagwx; no sobrescribe el historial ni una configuración previa. Solo imprime fechas/scope, sin referencias privadas. No crea consentimiento, claves, procesos, grants o permisos remotos; el resultado es un borrador, no autoridad de despliegue ni prueba de procedencia criptográfica.

## Orden para el próximo ensayo

Preparar comandos, artefacto aceptado, reversión, consumidor/suscripción y página humana antes del ingreso. Tras lectura autorizada, ejecutar inmediatamente la preparación y verificar las dos fechas originales; montar el segundo paso y comprobar su disponibilidad. No dedicar la ventana activa a documentación, compilación, coordinación o investigación de navegador. Si un gate depende del owner, presentar una sola acción con alcance y vencimiento claros. No avanzar si no cabe en la ventana original.

El seguimiento exige propósito humano propio; la lectura no lo concede. Suscripción/callback nativos y revisión cloud siguen pendientes; una página montada o script local no prueba estos pasos. Si vence, conservar ese original como evidencia y cerrar: nada de renovar por demora, resetear presupuesto o acreditar PC-off. Antes de una nueva ocurrencia confirmar explícitamente que el owner está disponible, y preparar el recorrido completo. Max queda fuera de estas pruebas.
