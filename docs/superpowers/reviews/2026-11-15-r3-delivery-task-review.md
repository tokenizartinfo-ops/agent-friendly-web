## Important findings

I01 — Loader and parent do not share the same startup admission contract. F7:83,86–88 checks temp ownership/mode and realpath, records Node device/inode/size/mtime, and succeeds without checking all the parent's predicates. controls-boundary.py:32,47–50 additionally requires restricted path alphabets, length, a regular executable owned by root/current UID with no group/other write bits and executable bits. A Node binary already used successfully by setup/loader can be refused before launching controls. F7 success therefore cannot establish that the pinned interpreter is admissible to this boundary. The very early generic fallback was observed, but attribution to any particular predicate would require evidence absent from this run. Align admission with the trusted bootstrap, retaining the security checks, and distinguish the first failing layer with a predeclared closed diagnostic or suitably qualified private stage receipt. No raw path/error, guessed reason or new public schema field. The binding/validation implementations at boundary.py:4–53 and controls-boundary.py:4–53 are identical, which makes independent changes to this security-sensitive logic particularly prone to drift.

I02 — The B13 control does not produce a missing cwd. controls.mjs:15–24,62–63 populates work/output/finite-budget/readonly/R3 before the control. At :93 it prepends cd and rmdir to a copy of the wrapper. rmdir on that nonempty cwd fails, stderr is discarded, and the following wrapper runs there normally (:114). Given a functioning positive path, it can return the happy-path result and fail B13 in the baseline and all three mutants. Use an independently empty removable cwd or an equivalent real missing-cwd setup; verify the setup status and then exercise the unchanged wrapper. This is an offline prediction, not an observed failed ID.

I03 — The byte reader silently removes an unauthorized UTF-8 BOM. io.mjs:9–12 performs fatal decoding with the default BOM handling. EF BB BF followed by a valid canonical ASCII sample and LF is decoded into the same string as the valid sample. raw-sample.mjs:2–3 cannot distinguish it; the site binding/record paths also receive normalized text. Check framing on the bytes or preserve the BOM in decoded text so the pinned canonical ASCII receiver rejects it. A named BOM-prefixed otherwise-valid fixture distinguishes the implementations.

I04 — The case oracle can certify the wrong semantic result. controls.mjs:114–120 filters away extra blank lines and matches prefixes before JSON parsing. The available branch does not compare the returned sampleState, sample values or observed flag to the expected case. A02 (observed with unknowns) could replace A03 (not_observed), or A01 could lose known values, without this oracle noticing. The negative branch accepts a generic fallback even for cases meant to prove that valid Source provenance survives a missing/invalid sample. It also accepts unused extra keys when the literal canary/path is absent. Use an independent closed-wire check and per-scenario comparisons for the expected sample/provenance/reason/context, preserving exact framing and actual mutant IDs. A boundary that collapses D01 into the generic fallback or replaces A03 with A02 should be rejected for the intended reason.

I05 — Public “missing” can be reported for an existing file. emitter.mjs:20,23 maps every readFixed failure to source_missing/sample_missing. io.mjs:5,8–12 also fails for denied modes, hardlinks, oversize contents, changes during read and invalid UTF-8. For example D05's existing 4097-byte file becomes sample_missing instead of an invalid sample; an EACCES does not prove absence either. Preserve ENOENT as absence and classify validation/I/O failures with the existing closed choices or boundary fallback, according to what is known. The current permissive oracle at controls.mjs:120 masks this distinction.

I06 — The executable pathname is accepted from the binding and reopened after verification. boundary.py:47–53 and controls-boundary.py:47–53 compare the candidate's file metadata to values from the same mutable context and close that descriptor. Both :60 launch the pathname afresh. F7:86–88 initially writes the real Node path, but the parent has no independent fixed executable identity if the binding's path and metadata change together; even a check-to-exec pathname replacement can change what runs. A different private regular executable with matching self-declared metadata satisfies the check without being Node. The Node self-check occurs after execution. This is a conditional command-selection capability, not a report of tampering. Bind the allowed executable independently of the child-readable context, and execute the verified object or an equivalently protected fixed identity. Keep the fixed module and arguments. This finding concerns the explicit no-generic-command/path contract.

I07 — F7 lacks the outermost fallback when the wrapper itself cannot start. F7:96–98 runs /usr/bin/bash on the temp script, with stderr discarded and no status translation outside the script. If the script cannot be opened, no closed record is written. Unset RUNNER_TEMP under nounset is expanded before the command. The fallback in controls-boundary.sh:3–7 is available only after that script starts. F7:92's separate setup token also is not the contracted controls-unavailable record. Provide the trusted outer entry/fixed fallback where the interpreter or script can actually fail to start, while preserving exactly one public record and the nonzero result for a normally delivered unsuccessful report. The actual run did reach the wrapper and does not demonstrate this fault.

I08 — The final production parent accepts schema-shaped but semantically impossible child output. boundary.py:81–87 checks closed keys/types/ranges, context and equality of the delivery observed flag to the state. It omits sample association/absence predicates from raw-sample.mjs:20–24 and normalized-sample.mjs:17–21. A canonical envelope with sampleState=not_observed, inputSeeded=true, seedEntries=201, and delivery.sampleObserved=false passes these parent checks. A faulty untrusted emitter can thus publish a false sample marker. The narrowly inspected independent Root envelope receiver fc579ca30a7a2a6388a34740c8f4edaa2a73cb73:70–93 rejects this same record, but only after publication. Apply the normalized semantic receiver (or equivalent fixed independent checks) at the pre-publication validation point; this needs no new Native read, callback or business timer.
