# HOSTBRIDGE local: protocolo y plan antes de código

Alcance autorizado: composición Node interna con runner/transporte existentes, sin mount ni envío remoto. Solo archivos nuevos; fuente original y fixtures de Operations ajenas intactas. No SDK cloud ni atestación de VM. El host confiable es el agente que invoca herramientas soportadas, no un cliente HTTP.

## API y protocolo exactos

`createOccurrenceHostBridge({input, output, pins, now=Date.now, timeoutMs=10000})` devuelve `{preflight({signal}), close()}`. Pines copiados y validados: sourceRevision (40 hex), configId, publicationId. Un request pendiente, máximo seis por vida del bridge, ningún retry. Timeout configurable solo reduce límite (1..10000 ms). Salida NDJSON exacta: `{version:'afw-host-observe-v1',type:'observe',id:1..6,nonce:UUID,startedAt:integer}`; entrada exacta: `{version,type:'observation',id,nonce,cloud:{configId,publicationId,configurationRevision,observationRevision,observationsCurrent,networkMode,networkEnforced,operationsBindingsReady}}`. Cloud projection la prepara el host desde environment_status real, nunca env/secret values; helper puro `projectEnvironmentStatus` valida IDs con namespace, revisiones y ambas custodias con target/domain exactos, rechazo missing/stale/error. Input no elige fuente, origen, paths, timestamps ni permisos. JSON UTF8 estricto <=2048 bytes por frame; campos extra, unsolicited/duplicate/replay/out-of-order/error/EOF/abort/timeout invalidan permanentemente bridge. Frames observación no anuncian readiness global.

Git lo lee el proceso en cada preflight desde la ubicación real del módulo runner importado (no cwd del host/request). Seis lecturas Git locales con argv fijo: raíz, HEAD, origin, porcelain con untracked, origin final y HEAD final. Los pines deben coincidir al inicio y final; carreras que cambien HEAD/origin entre lecturas deniegan. Origin debe ser literal canónico sin credenciales; HEAD exacto del pin; dirty incluido untracked falla cerrado. Son observaciones durante un intervalo, no lock del checkout ni prueba de que no cambiará después. Comando no publica stdout/stderr Git en errores. Máximo 3 s por lectura, subordinado al timeout/cancel del request; cero fetch/reset/checkout. Pruebas helper Git usan módulos dentro de repositorios temporales reales, no un mock que declara limpio.

`runAssistanceHttpOccurrenceWithHostBridge(options, streams)` crea bridge y llama al runner canónico con su preflight; no acepta preflight alternativo; finally close. El bootstrap servidor/host suministra manifest, digest y transporte, nunca stdin. CLI `scripts/afw-occurrence-host-bridge.mjs sourceRevision configId publicationId` ejecuta UN solo probe de metadata, no runner/HTTP ni lectura de credenciales; emite resultado exacto `{version,type:'probeResult',accepted:boolean}`. Fallo saneado sin stack/details. Es herramienta local preparada, no activación automática.

## Tiempo y confianza

startedAt = reloj Node antes de Git/observe; recibido <=10 s, reloj no retrocede. observedAt entregado al runner = startedAt, significado `retrievalIntervalStart`, no edad interna del check cloud. environment_status no publica provider timestamp; no inventarlo. Obtener snapshot actual durante intervalo no prueba que la plataforma volvió a comprobar custodias entonces. Runner conserva freshness/deadline/lease checks y presupuesto HTTP 3 operaciones + 3 controles + stop <=7. IPC: <=6 status invocations host + <=36 lecturas Git proceso; adicionales claramente fuera del presupuesto HTTP operacional pero dentro de cómputo/control local. Host debe usar una llamada supported environment_status por observe, responder una vez, descartar resultados posteriores a cancel. Cancel local no afirma abortar herramienta host sin primitive soportada.
