## Design / scope
createDelegatedPreparationAuthorizationHost(options) returns null by default. Exact enabled:true + issuer/env/original preparation-consent profile creates the actual OAuthAuthorizationServer1.2.1 and returns {authorizationServer,fetchToken}. The AS is available to existing consent/MCP source adapters. fetchToken is ONLY POST /oauth/token, public own client authorization_code+PKCE; no registration, refresh, revocation, connections or production Worker route. Complete withdrawal/connections integration remains next. Original read Worker unchanged.
Choose a source-owned AS with request-local AsyncLocalStorage, rather than a mutable global current-request callback or another arbitrary SDK callback implementation. Cost: Worker nodejs_compat is required; native CI verifies the actual pinned combination.
Callback authority exists ONLY inside fetchToken's original opaque request lease/context; calling AS.fetch directly cannot create application authority. Same profile dates/project/client/resource remain immutable. Host config/global clock drift terminal; one expired request must not poison a later valid original-profile request.

## Token sequence
Same original5s lease starts BEFORE URL/body/SDK/rate/storage; form actual4096bytes, URL8192bytes, JSON response32768bytes. Known single fields grant_type/code/code_verifier/client_id/redirect_uri/resource/scope; no browser identity/expiry/profile/approval. grant_type authorization_code only, exact pinned public client/resource, optional Origin absent or same issuer. AS validates actual code/PKCE/client/callback.
Rate limiter uses hashed fixed client/resource key before SDK. AS request env is captured trusted env, not callback-supplied authority. Callback requires exact SDK env, authorization_code, client+subjectClientId/userId/resource/props, underlying granted scopes EXACTLY the admitted choice and requested scopes a read-containing subset. No evidence, prepare-only, arbitrary grant or cross-client exchange.
Resolve ONLY the consent row bound to applicationGrantId/subject/profile/project/client/resource/originaldates; existing explicit store.inspect supplies its journal/owner/domain/revision/absolute expiry/scopes fences; explicitly reuse checkAgentCapsulePreparationSchema before consumption, callback completion and final token response. Preserve the original HTTP requested scopes in request-local state, reject additions beyond the granted ceiling even if SDK downscope would silently drop them. Use existing primary OAuth store.consumeExchange once. Unknown ACK -> no automatic retry/new code/key; retain finite history. A null/competing result must not revoke another winner.
After a valid acknowledged consumption capture its exact own grant BEFORE fallible current checks. Reinspect current persisted receipt and owner/schema and original remaining time before returning TTL=min90,floor(originalExpiry-now)/1000; refreshTokenTTL0. No new props/scopes/cross-client authorization.
SDK1.2.1 automatically revokes a provider grant on callback invalid_grant. Unowned/unknown callback failures therefore use generic temporarily_unavailable503, avoiding an implicit foreign/winner revocation. Only a known acknowledged own consumption may schedule the existing scoped app-grant revoker.
After actual SDK token issuance, validate the token via the same actual server, exact props/user/client/resource/scopes, integer Unix expiry<=original consent/profile expiry, current primary receipt and scope; expose only bounded standard token fields. Recheck before response handoff, without promising network ACK. No callback-level success alone certifies the final HTTP result.
Known-own pre-handoff failure/deadline schedules ONE scoped privilege-reducing revocation with finite2000ms waitUntil grace. Late actual acknowledged work is observed for that same cleanup; no extended response/authority budget or cleanup-success claim. An SDK token committed after deadline must never be returned, and current D1 denial must block it after known-own withdrawal. Lost consume ACK remains uncertain/finite, not labelled a successful withdrawal.
No remote DDL/client/scope/grant/token/permission/deploy/Container/event action. No G2 repeat/OTP/Max/mail/PCoff claim.

## SDK minimum lifetime qualification
Pinned provider1.2.1/KV require accessTokenTTL>=60s. Before consuming application permission, reserve the entire remaining ORIGINAL request budget inside the admitted absolute expiry; reject if fewer than60 whole seconds remain after that reserve. Recheck after async work; no rounding-up or renewal. Native original55/59/60s profiles reject without application consumption/withdrawal; original70s qualifies actual token/MCP. This deliberately closes new exchanges slightly earlier than grant expiry.
