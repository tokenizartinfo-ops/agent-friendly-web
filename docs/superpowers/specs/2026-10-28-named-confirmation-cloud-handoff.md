# Named confirmation public cloud handoff
Project AFW only; repository tokenizartinfo-ops/agent-friendly-web; build-only GitHub Actions and immutable public artifact refs. Existing authorization covers source/CI/cloud handoff; no runtime or permission action is part of this block.

## Problem
The accepted publication template has a verified cloud Git handoff, but the named confirmation package freezes historical Worker code while using newer operator code. Its8file artifact also contains compiled inert index/policy/frozen-artifact outputs that must not be selected for the public template handoff. Reusing the publication helper would incorrectly require both revisions to be equal.

## Design
Add a separate strict helper accepting exactly4public strings: template.mjs, materializer.mjs, template.json and private-template-build.json. Independent accepted-source inputs are operator commit/tree, exact recorded8field frozen pin and materializer SHA256. Capture all descriptor-checked primitives before awaits. Require distinct provenance to match their respective pins, exact receipt shape/false authority flags, all hashes/bytes/bounds and the native fixed-target artifact key. Validate the confirmation manifest/slot with the existing standalone pure materializer using only an expired0/1 synthetic policy; do not execute downloaded code. Hash/shape checks are not consent or native runtime acceptance.

Chunk raw UTF8 bytes at48KiB, encode base64 and provide Git blob SHA1s. Preserve operator and frozen provenance separately in a versioned public index. Fixed create-only ref artifacts/afw-named-template-OPERATOR40HEX. No private policy, materialized index, frozen-artifact JSON, credentials, owner/callback fields or live authority are included by this build contract. Publication helper/format stay unchanged.

Extend existing named package workflow: read-only package job validates public4file subset and uploads it separately only after existing exact historical rebuild +23native inert qualification tests. Separate contents:write/actions:read job runs only successful main workflow_dispatch, checks out that exact source, downloads same-run public subset, derives independent Git/source pins and hashes from checkout, recomputes descriptor, validates Git tree against expected paths/modes/types/hashes, then creates orphan ref once. Existing ref is accepted only if identical tree; no update/force/delete/retry. PR runs cannot preserve; no new long-lived credential.

## Acceptance and limits
RED availability test must fail before helper implementation; GREEN tests include separate revisions, tamper and format confusion, extra/private files, exact pins/hashes, byte caps/getters/mutation capture, raw UTF8 multibyte crossing and receipt roundtrip. FullCI/lint/build +existing named native package qualification +one final whole-branch read-only review. Then accepted main dispatch once and independent immutable blob readback/reassembly/inert assembly entirely cloud. No real live policy, native Workflow invocation, reservation, grant, OAuth, Container or PC-off claim. Rollback source commit retains prior workflow and refs; never overwrite historical snapshots.
