# Finite Source qualification with one admission clock

**Decision proposed to Root, 2026-11-15.** Use one GitHub `readonly` job, one main-thread controls scheduler, two in-flight case slots, stable group barriers and actual per-instance readback. Keep the 90,000 ms clock and 20,000 ms admission reserve. Permit completion in a different order within a group. Keep matrix dispatch, result publication and kill-set order canonical. This is a design for I3. Its completion criterion is one fresh actual 520-instance qualification and strict job-bound readback.

## What the design changes

Receipt `c0a582f6c8e5d786c90cf0297e45dfb0bf21d7e6` binds instrumented Source `e10fc5bb`, run `43745210412`, attempt 1, job `132906890534`. Baseline, M_RAW and M_PROVENANCE each finished 104. M_OUTPUT entered 96 cases, observed B05/U01 and hit the inner admission gate. M_ASSOC hit the outer gate with zero entries. All 408 entries returned known results. There was no exception marker. I3 lacks 112 measurements. The old loop closed 5/5.

Normal CC1 raw `f23fcfebf3c72632327cf24babf2ff7ace22dae6`, index `1a40f535b1e9d25c327a3ca02c337f807f3db382`, is the design baseline. In `controls.mjs` `b9b58c4a`, lines 23–24 set the global deadline and admission rule. Lines 39–51 allocate a case-private work/temp/helper tree. Lines 53–59 synchronously wait for each role. Lines 242–280 apply mutations and call the existing oracle, including real process-loss probes. Lines 282–307 currently serialize all five groups and publish v1. Each L01 explicitly waits at least three seconds after observing its sleeping emitter. Slot two can advance during that wait. Runner throughput is unmeasured.

Also cut redundant preparation without changing input bytes. A complete nominal pass enters `retargetEntries` 104 times before scenario staging and 100 times after it per group (the four prestart rows deliberately skip the second call). Each call computes six pins for three distinct byte inputs. Compute each pin once per call and reuse it for the same bytes. Across 520 nominal cases this removes 3,060 gzip operations from this function alone. Keep both rewrites, unique needle checks, actual on-disk bytes and order. A bounded three-entry memo for the pristine kernel and two pristine outer modules may be used only on full-byte equality, after reading actual case bytes. An altered input takes the real pin path. Check byte-for-byte equivalence for all mutant and scenario variants. Wall-time savings remain unknown.

## Scheduler and physical ownership

1. Keep the exact literal global deadline assignment so nested T01 genuinely replaces it with an expired deadline. On the original controls Node main thread validate retained fd3 against the current image, version, Source/tree/run/attempt/job binding and pinned matrix. Capture the real main-thread creator FD and snapshot pristine helpers, source-literal launcher, immutable order, expected kill sets and oracle authority before any new await. Charge all new scheduler loading/initialization to the already-running deadline. Load the one builtins-only internal module from the pinned immutable bytes, after this check, without a caller-provided import path or body. Revalidate this original creator handle at later forks. Allocate a fixed five-by-104 ledger initialized unattempted. Only the top scheduler owns it. Production18 remain DATA.
2. Within each of baseline, M_RAW, M_PROVENANCE, M_OUTPUT and M_ASSOC, one synchronous dispatcher reserves the next canonical index only when a slot is free **and** the original admit predicate is true. Mark actual entry at the start of `execute`, exactly once. Never enqueue 104 pre-admitted promises. If admission closes, retire started work under its original clocks and leave the tail unattempted. Advance groups only after both slots retire. Keep running after an expected mutant kill.
3. Keep `build`, scenario edits, mutations, `counterexample`, `accepts`, the role allowlist and case working directory semantics. Make `execute`, `executeOne`, the FIFO branch of `change` and `runRole` await the physical operation. This includes make-fifo before sample use, /dev/full's second role before closing the FD, witnesses and lifetime controllers. Retain the case object, unique instance key, all promises, process handles, FDs, spools and external inode witness until terminal ownership is established. Each slot owns at most one active role. Key H01 external names by unique canonical instance ordinal, avoiding map-size reuse. Keep one coordinator allocating directories, verifying each case base's initially captured device/inode, and reducing results in fixed order.
4. Keep the actual initiating controls **main thread** as creator of the role custodian. Open its own `/proc/thread-self` and verified case helper directory synchronously, construct the closed role, frozen launcher bytes, env allowlist, cwd and image fd3 before spawning. Install listeners, stdout/stderr drains, deadline and physical promise ownership before yielding that launch. Following a prior awaited subrole, revalidate the held case and clock, acquire the actual creator FD for this new fork and launch synchronously. Never reconstruct an earlier parent identity from a later PPID, accept a caller PID/path/callback/program, use a worker thread as the creator, or substitute a PATH-selected Node. Preserve fd6/7 identities, initial fd5 literal installation/inheritability/seals and the distinct L05 FIFO fd8 inside the tested lineage.
5. Add one private test-only custody operation to the **top controls runRole launcher only**. A nominated Source helper supplies a fixed launcher derived at a unique checked seam of the pristine Python literal. Retain verification, sealing and exec of the original role body, and keep all nested stock entry files byte-identical. Before forking, this launcher validates and arms its real Node creator with the CC1 fd4 main-thread/start-identity, native `getppid` guard, PDEATHSIG set/get and post-check. Set/read back `PR_SET_CHILD_SUBREAPER`, require a single-threaded process, default SIGCHLD handling, and snapshot its own creator-directory FD. On the new fork install **this** parent's held main-thread FD as fd4, re-arm and validate the actual child relationship, then follow the normal fixed sealed kernel/role exec. No extra Python cold start is needed for the waiting parent. An exec preserves creator identity, whereas a fork establishes a new one. Validate the original call chain and helper/kernel snapshots before interposing. A case may rewrite only its own existing test targets.
6. Use one private bounded control socket/pipe pair per launched custody process, e.g. parent-owned Node stdio[8] with the child end inaccessible to the tested role. Close the custody end in the fork child **before** executing any case code. It does not displace L05's own later fd8. Over this channel allow only one bounded READY monotonic sample, one START carrying an absolute restrictive cutoff, and cancellation by EOF. No user data or general command. The parent starts each case cutoff before case work, at most 5,000 ms and bounded by the global deadline. Each 3,000/5,000 ms role retains the smaller applicable limit, including repeat roles from the same case. For a READY sampled at child monotonic P and received at parent time R, send P + floor(remaining at R), rounded down in consistent units. The round trip only shortens the original cutoff. Parent rechecks its original clock before START and on readback. Child checks the absolute cutoff before fork and during wait. A bounded pre-START wait performs no case work. Unexpected, late or repeated frames, EOF, unsafe clock sample, or an ambiguous write permanently invalidate that instance. No second START. Retain the same physical promise through timeout/cancel, without a new permission window.
7. The custodian creates exactly one direct target, retains a verified pidfd for that child before reaping (capture while its identity belongs to this parent), and never signals a numeric PID, shared process group or arbitrary descendants. On timeout/cancel close admission for that role, signal only the held target when needed, and retain custody while reaping its own children. On successful retirement it must have reaped the original target, captured its exit status, reaped any adopted descendants and observed ECHILD. A live branch still has a direct child or adopted ancestor until extinction. This relies on the fixed closed fork/exec tree, one new subreaper per role, no ignored SIGCHLD, no namespace/process escape and a living custodian. The plan must inventory every allowed fork and FD inheritance. The waiting custodian alone maps fully drained target statuses 0,1,23 to distinct reserved transport codes (e.g. 80,81,82). Target stdout/stderr travel unchanged. Infrastructure failure, unexpected status, signal or lost custody cannot produce a valid mapping. A lost ACK stays unknown.
8. Node uses fixed async spawn, no shell/detach/unref. Byte-limit both pipes while continuing bounded discard/drain after overflow; sticky failure. Preserve per-call 8,192/32,768 bounds and inner stdout/stderr limits, UTF-8/framing/status checks and empty stderr rules. Cap control messages at 64 ASCII bytes each and one per direction. A completed spawn/kill/exit or a child-provided JSON record cannot alone release a resource. Require the same handle's final close, EOF and custodian terminal mapping. Catch error-before-spawn, error after spawn, EPIPE, timeout/late close and double notification separately. Only demonstrable pre-spawn failure releases an unused case with no consumer. With uncertain custody stop new admissions, mark affected cleanup unknown, retain its files and private image and fail the job. A still-pending handle stays fenced until an existing independent parent/outer/job watchdog ends the run. Never spin, invent success or delete resources to make the watchdog return.
9. Start the one cleanup deadline at eligibility for the original case, min(global end, now + 2,000 ms), keep it across every cleanup action, and accept no late success. Use the original 256-visit, owned, no-follow, directory-FD-identity checks and hardlink external-inode verification; preserve the exact original witness. Only drained roles or cases demonstrably free of consumers qualify for deletion. Record failed/unknown cleanup by actual instance, sorted canonically and disjoint. No recursive cleanup of a quarantined root. Empty owned sandbox removal, if performed, requires terminal ownership and exact empty directory identity. F7's private image removal remains success-only.

Node distinguishes process exit, pipe closure and errors. Linux reparents an orphan to its nearest living subreaper. A new fork must arm its own parent-death contract. The cited Node documentation is 22.23.0. Actual compatibility on pinned 22.23.4 remains a test obligation. ## Alternative and rulings

A static matrix of five isolated GitHub phase jobs, each running one complete group serially, is technically viable under a different specification. It preserves the synchronous case role and nested v1 controls by using one separate trusted phase driver derived from normal execute/mutator/oracle code. Bind five static matrix names to five fixed bootstrap phases. Keep nested test context job key readonly while joining five **distinct** numeric job IDs; the display name is not the job key. Phase-boundary/outer must capture and strictly validate a new closed phase schema and fallback, then publish only a phase frame. Bind each phase to its pinned literal, group/vector/cleanup, Source/tree/run/attempt and Node. Never fabricate a v1 full-controls pass in a phase. Root would need a new composite receiver for one static push attempt, all five successful jobs/steps and unique real phase frames; it could not pass these jobs to a1c as one job or hand a composite to v1 delivery. Failure/absence/late arrival of any job leaves the composite unqualified.

That alternative gives five 90-second admission contexts, up to five private images and up to 35 runner-minutes versus seven. It requires an explicit global closure policy, e.g. a one-use Source-only absolute window fixed before the push, at most seven minutes, checked before each job's Source entry and at completion, with per-phase deadlines clipped to it and Root independently rejecting late/queued work. Jobs may queue and expire. Physical per-role fences and unknown quarantine still apply independently in each job. Per-phase child/cleanup bounds, absence of renewals and exact root consumption would require separate review. Five reported phase successes cannot prove the original single-harness elapsed bound. Prefer the two-slot design because it preserves that bound, a single actual job and the existing Source proof shape. Serial compression reuse alone has a deterministic work reduction but no measured evidence that it recovers enough wall time.
