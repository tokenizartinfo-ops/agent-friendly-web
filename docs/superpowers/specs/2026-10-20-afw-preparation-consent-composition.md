## Composition decisions
At request entry create the existing original opaque5s lease. Fixed synthetic profile/trial lives in runner memory. SDK parse creates verified request; hash a canonical explicit packet(response type/client/redirect/scope/state/PKCE/resource/issuer). No caller/form authority for subject/profile/project/timestamps/hash. Persist original starts/ends and server-current expected revision through PR514 begin before rendering.
GET JSON remains available only for runner protocol clients; Accept:text/html invokes the PR513 renderer with persisted original dates/scopes, escaped synthetic labels, fresh CSP nonce and SDK binding cookie. Only handle/decision travel in the form; unknown or repeated keys rejected.
POST uses original subject/profile/hash record, pure policy and primary store inspection. Call SDK approveConsent WITHOUT a scope override, so its cookie-validated return retains the original full request; compare its canonical fingerprint to stored hash. Only afterward admit the visible subset through PR514 and pass that exact fresh result to completeAuthorization. No scope widening, code completion from inspect, reused original window or second grant. SDK KV read/delete is not an atomic winner; D1 fresh decision controls completion.
Cancel uses SDK deny plus application cancellation, never creates a grant; actual grant withdrawal remains the existing revoker.
A private scoped primary lookup in the fixture captures its internally generated grantID solely for failure cleanup. Reservation/admission/code ACK fault occurs AFTER the real corresponding side effect. Unknown store ACK yields no Location/code and leaves a possible committed application grant unexchanged under its original finite expiry; it MUST NOT revoke a competing fresh winner. Only this request's fresh acknowledged admission owns privilege-reducing cleanup if subsequent SDK completion fails/ACK is lost. That known-own grant is revoked through the existing revoker; historical consent remains. No retry or resumed code completion from read recovery. This lookup is not a public/MCP recovery API or authenticated production authority.
Token exchange continues actual SDK callback/consumeExchange, bounded by original application grant expiry, current owner/domain/schema and exact scope/client/resource. No refresh, registration or publication privilege.
