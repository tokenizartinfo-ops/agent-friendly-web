# Host finito del token de preparación
20oct2026. Fuente candidata; evidencia final en PR519/issue497. Sin montaje productivo ni operación remota.
La fábrica crea el servidor OAuth real del SDK y una frontera de intercambio de código, desactivada por defecto. Conserva el cliente, expediente, recurso y fechas originales; no registra clientes, ofrece refresh, publica o cobra.
Cada solicitud tiene el mismo plazo original de cinco segundos desde antes de leer su cuerpo. El callback usa contexto aislado por solicitud y el consentimiento persistido actual; no puede obtener autoridad invocando directamente el servidor SDK fuera de esa frontera.
El código y PKCE los comprueba el SDK. AFW contrasta la elección visible, propietario, revisión, dominio, esquema y permiso antes y después de consumir una sola vez la concesión. El token real se verifica antes de entregarlo, con alcance y vencimiento iguales o menores al permiso original; nunca se devuelve refresh.
Una confirmación desconocida detiene el recorrido sin reintentar ni retirar un posible ganador. Si se confirmó el consumo propio y falla el recorrido antes de entregar la respuesta, se intenta una retirada acotada y única. Una demora de KV no puede entregar el token después del plazo. La limpieza no certifica recepción del cliente ni retirada remota exitosa.
El SDK1.2.1 tiene una retirada automática asociada a invalid_grant del callback. La denegación desconocida/no propia usa un error temporal genérico para evitar esa consecuencia sobre terceros; no invita a repetir la solicitud automáticamente.
