# Consentimiento humano para avisos — interfaz privada preparada

El recorrido de lectura existente sigue separado. `createDossierMonitoringOwnerHandler` prepara una pantalla HTTP del mismo issuer/recurso OAuth con un proyecto, conexión y cliente propios fijados por servidor. No está enlazada al Worker OAuth ni desplegada: no hay autorización humana real, migración remota, flag de Events, nueva clave ni suscripción cloud.

La interfaz muestra una decisión por vez, tipografía comic en todo el cuerpo, papel cálido/tinta/verde y controles accesibles. Explica que los avisos incluyen referencias y fechas, que el asistente debe consultar nuevamente lo permitido y que un aviso no acredita revisión terminada. La confirmación guarda una decisión, no inventa una suscripción. Retirar avisos no desconecta la lectura ni borra el expediente. HTML probado no acredita todavía la comprobación visual 1440/390 ni disponibilidad del font en un navegador real.

## Contrato y guardado

El host suministra una política propia cerrada por defecto, origen HTTPS canónico, proyecto/grant/cliente/recurso y ventana <=10 minutos, D1 y el verificador Access existente. La política se copia sin getters; el cuerpo nunca suministra esos datos, identidad, custodia ni ámbito. `enabled !== true` no verifica identidad ni lee DB. Origin, método, ruta y parámetros son estrictos; errores estáticos no incluyen datos ni afirmaciones sobre la causa. Solo después de verificar la firma/issuer/audiencia se lee el `exp` del mismo assertion, se exige `sub` idéntico y vencimiento válido. Ese plazo original limita ticket/permiso y fence SQL; no se usa `decodeJwt` como autenticación.

GET verifica Access y dueño actual del mismo grant/proyecto. Guarda únicamente un formulario inmutable con hash de un nonce aleatorio de 256 bits, propósito `afw.dossier-monitoring-owner.v1`, solicitud UUID, acción, revisión, secuencia y plazos originales. No guarda el nonce, JWT ni bearer. GET no concede seguimiento. Una cookie `__Host-` Secure/HttpOnly/SameSite=Strict acompaña el formulario; POST exige Origin exacto, una sola cookie, cuerpo <=1024 bytes y un solo handle. El formulario se liga a usuario/grant/proyecto/cliente/recurso/propósito/acción originales y vuelve a verificar Access tras las esperas.

POST compone el journal de PR398: CAS, dueño/revisión actuales, scope all-string, original OAuth y retiro terminal. Un nonce solo puede producir la operación UUID original; el reintento obtiene su recibo sin renovar. Dos formularios concurrentes diferentes solo producen un grant. Las nuevas condiciones opcionales `expectedClientId/expectedResource` y `commitWindow` se fijan por servidor y se comprueban en la misma inserción SQL; el reloj nativo impide guardar después del vencimiento aunque la observación JS se haya quedado atrás. Son checks adicionales, no una autorización alternativa. El antiguo contrato sin estas opciones se conserva para los callers internos existentes. El callback trusted `beforeCommit` vuelve a verificar Access después de la consulta de recuperación, antes de insertar o devolver un recibo. La ventana SQL del formulario es el mínimo de ventana original/ticket/Access firmado, nunca una ventana renovada.

El retiro tiene su propia acción y formulario; el owner vigente puede retirarlo dentro de la ventana de QA aunque OAuth ya haya vencido o se haya revocado. No habilita lecturas con OAuth inválido. El journal y tickets bloquean UPDATE/DELETE por triggers; esto no prueba protección contra administradores que restauren o eliminen la historia. Debe resolverse esa custodia antes del montaje.

## Evidencia y próximos pasos

TDD: API ausente, vencimiento de SQL y cambio de cliente al commit reproducidos antes de corregir. SQLite nativo cubre CSRF, acción/owner/revisión, identity inválida, scopes corruptos/revocación, ventana, formulario duplicado/excesivo, concurrencia, retiro e idempotencia. Workerd/D1 nativos verifican la firma RS256 Access mediante JWKS generado de fixture y el circuito GET/grant/retry/withdraw. La clave y sesión son sintéticas y locales; no sustituyen una cuenta real. El ensayo calcula su ventana dentro de `/seed`, no durante carga global del Worker.
