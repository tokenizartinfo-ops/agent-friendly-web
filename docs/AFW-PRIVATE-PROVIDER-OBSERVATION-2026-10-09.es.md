# Lectura privada de proveedor con inventario acotado

Preparación interna, 9 octubre 2026; avance parcial de Task2 del plan de provisioning. `createPrivateProviderObservation` lee por GET el token, settings, schedules, política y aplicación exactos, y pagina el inventario de tokens de la cuenta y las políticas de esa aplicación. Los recursos proceden de inscripción/aprobación completas V2 y el dominio/audience de configuración administrativa privada, nunca del consumidor.

Solo el dominio propio `operations-manager.agentfriendlyweb.dev/assistance/custody/confirm` es admisible. Se exige una única política de servicio `non_identity`, con el selector exacto del token y sin reglas adicionales include/exclude/require; la aplicación, fechas de creación/vencimiento, metadata de identidad y token activo deben coincidir. Una configuración cerrada/deny-all sigue devolviendo no disponible. No ampliar Access para conseguir una prueba positiva.

Dos pasadas de lecturas deben coincidir. Se comprueban paginación, total, IDs únicos y fuente administrativa antes/después. Hasta cuatro páginas de cien elementos por lista y máximo26 GET; una cuenta mayor queda no disponible hasta diseñar otro presupuesto explícito. El plazo total por defecto es cinco segundos y como máximo diez. Timeout aborta la señal y cierra lógicamente la lectura; una respuesta tardía no inicia más solicitudes. El transporte del host debe respetar AbortSignal, limitar cuerpos y fijar credenciales/origin del proveedor.

Salida privada `afw-private-provider-observation/v1`, estado `observed`: fecha, referencia del registro, fechas/estado/digest del token y digests de las lecturas e inventario. No client_id, claves, cuerpos originales ni autoridad de instalación. Los timestamps observacionales updated_at/last_seen_at no se presentan como versión del secreto. La metadata fijada se valida mediante el contrato existente, con versión opcional solo si la fuente la aporta realmente.

El inventario significa metadata de tokens de la cuenta y políticas de la aplicación propia. No demuestra uso exclusivo del token en aplicaciones ajenas ni custodia global. La reserva primaria CAS de recursos sigue siendo necesaria. Falta resolver y correlacionar originales cloud/diario primario, producir autoridad y coordinar instalación/retirada. Una función callback o respuesta sintética no acredita procedencia operativa por sí sola.

Sin montaje, rutas, binding, credenciales nuevas ni mutación remota. Las pruebas locales validan el comportamiento del lector, no un provisioning real ni una ejecución con PC apagada.

El transporte separado `createPrivateProviderGetTransport` conserva la implementación de cierre existente: fija `https://api.cloudflare.com/client/v4`, siete paths propios, GET sin redirects ni retry, query de inventario exacta page1–4/per_page100 y cuerpos JSON de hasta262144 bytes. La custodia se resuelve fuera del consumidor. La cancelación externa o deadline bloquea también un fetch tardío tras esperar la credencial. Se conserva `result_info` para validar count/page/per_page/total_count/total_pages; ausencia o incoherencia se rechaza, nunca se inventa un total.
